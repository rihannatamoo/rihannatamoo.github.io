THE WORKFLOW

The product was designed around time lost to repetitive documentation, not around adding AI everywhere.

The key product decision was where intelligence should enter the workflow. AI was most valuable where users were repeatedly gathering context, rewriting information or producing similar documentation from source material.

PRODUCT PRINCIPLEAutomate repetitionKeep judgment with the user.
BEFORE

Manual documentation loop

  • Gather context from multiple places
  • Rewrite and structure information manually
  • Repeat the process for similar documents
  • Spend time on formatting and rework
AFTER

AI assisted workflow

  • Capture relevant context once
  • Generate a structured first output
  • Review, correct and approve
  • Reuse the workflow across documentation jobs
PRODUCT EXPERIENCE

Make the value obvious from the first use.

Adoption depended on users understanding quickly what the product could save them. I worked on onboarding and feature flows that shortened the distance between signing in and seeing a useful AI assisted result.

AI QUALITY

Better output required better context, not just a different model.

The product work improved how context was supplied and used so generated output became more relevant to the task. This is a core AI product lesson: model capability matters, but the surrounding product architecture determines whether the result is actually useful.

01

Context before generation

Make the source information explicit so the AI can ground the output in the actual workflow.

02

Structured prompts through product design

Use the interface and workflow to guide the task rather than expecting users to become prompt engineers.

03

Human review by design

Generated content is an acceleration layer, not a replacement for final user judgment.

04

Measure relevance

Track whether users keep, edit or abandon outputs rather than treating generation itself as success.
